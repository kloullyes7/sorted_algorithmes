## 2. Introduction

This project aims to implement, test, measure and compare five classical sorting algorithms using the C programming language.

The implemented algorithms are:

1. Bubble Sort
2. Selection Sort
3. Insertion Sort
4. Merge Sort
5. Quick Sort

The program provides an interactive menu that allows the user to execute individual sorting algorithms or compare all five algorithms using different array sizes.

The project also includes execution time measurement, large-array testing, and the export of comparison results into a CSV file.

No built-in sorting functions are used in the implementations.

## 5. Implemented Sorting Algorithms

### 5.1 Bubble Sort

**Principle:**

Bubble Sort repeatedly compares adjacent elements and swaps them if they are in the wrong order.

During each pass, the largest remaining element moves toward the end of the array.

The implementation uses an early-exit flag (`swapped`). If no swap occurs during a pass, the array is already sorted and the algorithm stops.

**Complexity:**

| Case         | Time Complexity |
| ------------ | --------------- |
| Best case    | O(n)            |
| Average case | O(n²)           |
| Worst case   | O(n²)           |

**Space complexity:** O(1)

**Advantages:**

- Simple to implement.
- Easy to understand.
- Efficient for an already sorted array with the early-exit optimization.

**Disadvantages:**

- Very slow for large arrays.
- Performs many comparisons and swaps.

---

### 5.2 Selection Sort

**Principle:**

Selection Sort divides the array into a sorted part and an unsorted part.

At each iteration, it searches for the smallest element in the unsorted part and swaps it with the first element of that part.

The sorted section grows until the entire array is sorted.

**Complexity:**

| Case         | Time Complexity |
| ------------ | --------------- |
| Best case    | O(n²)           |
| Average case | O(n²)           |
| Worst case   | O(n²)           |

**Space complexity:** O(1)

**Advantages:**

- Simple implementation.
- Performs a limited number of swaps.
- Does not require additional arrays.

**Disadvantages:**

- Always performs approximately the same number of comparisons.
- Inefficient for large arrays.
- Does not benefit significantly from an already sorted array.

---

### 5.3 Insertion Sort

**Principle:**

Insertion Sort builds a sorted array progressively.

Each element is taken from the unsorted part and inserted into its correct position within the sorted part on its left.

The algorithm shifts larger elements to the right to make room for the inserted element.

**Complexity:**

| Case         | Time Complexity |
| ------------ | --------------- |
| Best case    | O(n)            |
| Average case | O(n²)           |
| Worst case   | O(n²)           |

**Space complexity:** O(1)

**Advantages:**

- Simple and efficient for small arrays.
- Performs well on nearly sorted data.
- Uses very little additional memory.

**Disadvantages:**

- Inefficient for large, randomly ordered arrays.

---

### 5.4 Merge Sort

**Principle:**

Merge Sort is a divide-and-conquer algorithm.

It works in three main steps:

1. **Divide:** Divide the array into two halves.
2. **Conquer:** Recursively sort both halves.
3. **Merge:** Combine the two sorted halves into a single sorted array.

The process continues until the subarrays contain only one element, then they are merged progressively.

**Complexity:**

| Case         | Time Complexity |
| ------------ | --------------- |
| Best case    | O(n log n)      |
| Average case | O(n log n)      |
| Worst case   | O(n log n)      |

**Space complexity:** O(n)

**Advantages:**

- Efficient for large arrays.
- Stable sorting algorithm.
- Predictable performance regardless of the initial order of elements.

**Disadvantages:**

- Requires additional memory.
- The merging process involves extra allocations in this implementation.

---

### 5.5 Quick Sort

**Principle:**

Quick Sort is another divide-and-conquer algorithm.

This implementation uses the **last element as the pivot**.

The algorithm follows these steps:

1. Select the last element as the pivot.
2. Partition the array so that elements smaller than or equal to the pivot are placed on its left, while larger elements are placed on its right.
3. Recursively sort the left and right partitions.

**Complexity:**

| Case         | Time Complexity |
| ------------ | --------------- |
| Best case    | O(n log n)      |
| Average case | O(n log n)      |
| Worst case   | O(n²)           |

**Space complexity:**

| Case    | Space Complexity |
| ------- | ---------------- |
| Average | O(log n)         |
| Worst   | O(n)             |

**Advantages:**

- Usually very fast in practice.
- Efficient for large arrays.
- Does not require a separate merging array.

**Disadvantages:**

- Performance depends on the pivot selection.
- A poor pivot can lead to quadratic execution time.
- Recursive calls can become deep in the worst case.

## 8. Performance Measurement

### 8.1 Execution Time

Execution time is measured using the C library function `clock()` from `<time.h>`.

The execution time is calculated using:

```c
(double)(end - start) / CLOCKS_PER_SEC
```

The result is converted into milliseconds.

The measurement is performed around the sorting operation only, excluding array generation, copying and display.

For the comparison mode, each algorithm is executed five times on copies of the same original array, and the average execution time is calculated.

### 8.2 Memory Measurement

The program uses the `getrusage()` function from `<sys/resource.h>`.

The field `ru_maxrss` provides the maximum resident memory usage of the process.

On Linux, the value is reported in kilobytes (KB).

The memory measurement represents the peak memory of the process, rather than the isolated memory consumption of each sorting algorithm.

### 8.3 Benchmarking Methodology

To ensure a fair comparison:

- The same original array is used for all algorithms at a given size.
- Each algorithm sorts its own copy of the array.
- Array generation is excluded from the execution time.
- Printing is excluded from the execution time.
- Comparison measurements are repeated five times.
- Average execution time is reported.
- A fixed random seed is used to generate reproducible data.

## 12. Critical Analysis

The experimental comparison is expected to demonstrate significant differences between quadratic algorithms and divide-and-conquer algorithms.

Bubble Sort, Selection Sort and Insertion Sort generally have quadratic time complexity, O(n²), in their average and worst cases. Therefore, their execution time is expected to increase significantly as the array size grows.

Bubble Sort can perform better when the array is already sorted because of its early-exit optimization. Insertion Sort is also efficient for small or nearly sorted arrays. However, Selection Sort always performs approximately the same number of comparisons, even when the array is already sorted.

Merge Sort is expected to provide stable and predictable performance because its time complexity is O(n log n) in all three cases. Its main disadvantage is the additional memory required during the merging process.

Quick Sort is generally very efficient for large arrays and often performs well in practice. However, the choice of pivot can significantly influence its performance. Using the last element as a pivot can lead to poor performance when the array is already sorted or reverse-sorted.

The experiments are expected to confirm that Merge Sort and Quick Sort are more suitable for large randomly generated arrays than the quadratic algorithms.

Nevertheless, actual results depend on the experimental environment and the characteristics of the input data.

## 13. Limitations

The current implementation has several limitations:

- The memory measurement is process-level peak RSS, not an isolated measurement for each algorithm.
- The comparison CSV file records average execution time but does not include isolated memory values for each algorithm.
- The last-element pivot strategy in Quick Sort may produce poor performance on certain input distributions.
- The comparison mode skips quadratic algorithms for large arrays.
- The current comparison primarily uses randomly generated data rather than systematically testing all input types.

These limitations could be addressed in future versions.

This project implements five classical sorting algorithms in C and compares their performance through experimental testing.

It demonstrates the importance of algorithmic complexity when working with large datasets and highlights the differences between quadratic sorting algorithms and divide-and-conquer approaches.
